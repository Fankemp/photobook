# Photobook

Сервис подарочных фотокниг. Описание продукта, правила и план работ — в [CLAUDE.md](CLAUDE.md).

Готово:
- **шаг 1 — каркас**: Go-бэкенд, React-фронтенд, PostgreSQL, S3-хранилище, миграции, health-check;
- **шаг 2 — книга и шаблоны**: каталог шаблонов → просмотр шаблона → создание книги → книга по секретной ссылке `/b/<токен>`;
- **шаг 3 — редактор v0**: фото в слот (загрузка прямо в хранилище), сдвиг и масштаб кадра пальцем/мышью,
  автосохранение с черновиком на устройстве и защитой от затирания правок из другой вкладки;
- **шаг 4 — миниатюры и DPI**: миниатюры в фоне (libvips, с поворотом по EXIF), в редакторе — только они;
  предупреждение «Фото маленькое» на слоте, если для печати не хватает пикселей; уборка брошенных загрузок;
- **шаг 5 — превью**: книга по разворотам как после печати (с вылетами, без пустых рамок), линия реза
  и безопасная зона, сводка «что поправить» со ссылками на страницы в редакторе;
- **шаг 5а — текст и шрифты**: 10 шрифтов с кириллицей на своём сервере, правка текста из шаблона
  и добавление своего, шрифт, размер, выравнивание, жирность, цвет; автоподбор размера, если не влезает;
- **шаг 6 — заявка**: форма (имя, телефон, адрес, дата, комментарий) из превью, статус заявки для клиента,
  книга после заявки закрыта для изменений, сообщение команде в Telegram (через очередь в базе);
- **шаг 7 — админка** `/admin/`: список заявок с фильтрами, карточка (телефон, WhatsApp, превью книги),
  смена статуса с заметкой и историей; отмена снова открывает книгу клиенту;
- **шаг 8 — печатный PDF**: после заявки в фоне собирается PDF по настройке формата — по умолчанию один
  `book.pdf` (передняя обложка, страницы, задняя обложка); Chromium печатает ту же страницу, что видит
  клиент, с оригиналами фото и вылетами; PDF проверяется и скачивается из админки.

## Что нужно

- Docker с Docker Compose v2
- Для запуска без Docker и для `make test`: Go 1.27+ и Node.js 20.19+ (или 22.12+)

> Если у вас Go старее (например, 1.22), команды `go` в папке `backend/` сами скачают
> нужную версию (механизм `GOTOOLCHAIN`). Но лучше обновить Go: 1.22 уже не получает
> исправлений безопасности.

## Запуск

```bash
make up        # первый раз создаст .env из .env.example, соберёт и запустит всё
make ps        # статус сервисов: postgres, s3, backend должны быть (healthy)
make logs      # логи (Ctrl+C — выйти)
make down      # остановить; данные БД и файлов сохраняются в docker volumes
```

Без `make`: `cp .env.example .env && docker compose up --build -d`.

## Сервисы

| Сервис | Порт (только localhost) | Что это |
|---|---|---|
| `frontend` | 5173 | Vite dev-сервер, hot reload. `/api/*` проксирует на backend |
| `backend` | 8080 | Go API. При старте применяет миграции и создаёт бакет |
| `postgres` | 5432 | PostgreSQL 18 |
| `s3` | 9000 (API), 9001 (консоль) | [RustFS](https://github.com/rustfs/rustfs) — S3-совместимое хранилище |
| `render` | наружу не открыт | сборка печатных PDF: Chromium (Playwright), Ghostscript, poppler-utils, qpdf |

Порты меняются в `.env`, если заняты.

### Показать сайт кому-то (временная ссылка из интернета)

```bash
make share     # печатает ссылку вида https://….trycloudflare.com — её можно отправить
make unshare   # закрыть доступ
```

Работает через Cloudflare Quick Tunnel (бесплатно, без аккаунта): сайт по-прежнему крутится у вас,
пока включён компьютер и запущен `make up`. Туннелей два — сайт и хранилище фото (браузер грузит
фото прямо в хранилище), backend на время доступа выдаёт ссылки на публичные адреса. Ссылка
случайная и меняется при каждом `make share`. Открыть сайт может любой, у кого есть ссылка; админка —
по паролю. Для постоянной работы — деплой на сервер (шаг 10).

### Проверка с телефона (в той же Wi-Fi сети)

По умолчанию сервисы доступны только с этого компьютера. Чтобы открыть сайт с телефона:

1. Узнайте IP компьютера в сети: `hostname -I` (первый адрес, например `192.168.0.109`).
2. В `.env` раскомментируйте и заполните:
   ```
   BIND_ADDR=0.0.0.0
   PUBLIC_HOST=192.168.0.109
   ```
3. `make up`, затем на телефоне откройте `http://192.168.0.109:5173`.

Сайт и хранилище фото станут видны всем в этой сети — в общественном Wi-Fi так не делайте.
Кнопка «Копировать» ссылку без HTTPS на телефоне может не сработать — ссылку можно выделить вручную.
Вернуть как было — закомментировать строки обратно и снова `make up`.

**Почему RustFS, а не MinIO:** MinIO с 2025 года не публикует бесплатные Docker-образы.
Бэкенд работает с хранилищем только по протоколу S3, поэтому RustFS можно заменить
на любой другой S3 (SeaweedFS, облачный S3) правкой сервиса `s3` в `docker-compose.yml`.

## Разработка

**Frontend** — правки в `frontend/src` сразу видны в браузере.
Если поменяли `package.json`: `docker compose restart frontend`.

**Backend и шаблоны** — после правок пересобрать: `docker compose up --build -d backend`.
Или запустить локально против Postgres и S3 из Docker:

```bash
cd backend
export DATABASE_URL="postgres://photobook:photobook@localhost:5432/photobook?sslmode=disable"
export S3_ENDPOINT=localhost:9000 S3_ACCESS_KEY=photobook S3_SECRET_KEY=photobooksecret S3_BUCKET=photobook
export HTTP_ADDR=:8081   # 8080 занят контейнером backend
# TEMPLATES_DIR по умолчанию ../templates — для запуска из backend/ ничего задавать не нужно
go run ./cmd/server
```

**Тесты:** `make test` (Go-тесты, юнит-тесты фронтенда на vitest — кадр и DPI, линтер, сборка; один раз перед этим `cd frontend && npm install`).

**Сквозные тесты в браузере:** `make e2e` — Chromium (Playwright в Docker) проходит путь клиента:
`e2e/editor.mjs` — книга, фото с EXIF-поворотом, кадр, миниатюры, DPI, автосохранение, обрыв сети,
конфликт вкладок, превью; `e2e/text.mjs` — текст и шрифты: для каждого шрифта спрашивает у браузера,
каким шрифтом на самом деле нарисована кириллица (без подмены запасным), проверяет казахские буквы,
жирное начертание, автоподбор размера; `e2e/order.mjs` — заявка: несохранённая правка попадает
в заказ, подсказки под полями, статус, книга закрывается, старая вкладка редактора не перезапишет её;
`e2e/admin.mjs` — админка вместе с клиентом: пароль, смена статуса видна клиенту, отмена открывает книгу,
защита от подделки запросов (пароль для теста берётся из `.env`); `e2e/print.mjs` — книга с фото
(в том числе «лёжа» с пометкой EXIF) и текстом → заявка → PDF: страницы, размер, RGB, фото без пересжатия,
встроенные шрифты, скачивание из админки, защита печатной страницы, «Пересобрать PDF». Скриншоты — в `e2e/shots/`. Первый запуск скачает образ ~3.6 ГБ.

### Шаблоны

Лежат в [templates/](templates/), один JSON-файл = один шаблон. Формат и правила — в
[templates/README.md](templates/README.md). Сервер проверяет все шаблоны при старте и не
запустится с битым файлом; `make test` проверяет их без запуска.

### API

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | состояние сервиса и зависимостей |
| `GET /api/templates` | каталог: шаблоны без внутренних страниц, но с обложкой и форматом |
| `GET /api/templates/{id}` | шаблон целиком |
| `POST /api/books` `{"templateId": "…"}` | создать книгу по шаблону → `201 {"token": "…"}` |
| `GET /api/books/{token}` | книга (обложка, страницы, `version`) с форматом и списком фото |
| `PUT /api/books/{token}` `{"version", "cover", "pages"}` | автосохранение; `409 version_conflict`, если книгу уже сохранили из другой вкладки |
| `POST /api/books/{token}/assets` `{"contentType", "size"}` | начать загрузку фото → `{"assetId", "uploadUrl"}` |
| `PUT <uploadUrl>` | браузер кладёт файл прямо в хранилище (presigned URL, 15 минут) |
| `POST /api/books/{token}/assets/{id}/complete` `{"width", "height"}` | подтвердить загрузку; сервер проверяет файл |
| `GET /api/books/{token}/assets/{id}/image` | редирект на временную ссылку миниатюры (пока она готовится — оригинала) |
| `GET /api/books/{token}/order` | заявка (если есть) или данные для формы: `minWantedDate`, `priceKzt` |
| `POST /api/books/{token}/order` `{"name", "phone", "address", "wantedDate", "comment", "version"}` | оформить заявку → `201`; книга закрывается для изменений |

Ошибки приходят как `{"error": "код"}` (`book_not_found`, `unsupported_type`, `file_too_large`,
`bad_image`, `version_conflict`, `book_locked`, `already_ordered`, `invalid_phone`, …); текст для
человека фронтенд берёт из словаря по коду.

### Админка

`/admin/` — обычные HTML-страницы, которые отдаёт Go-сервер (`backend/internal/admin`, шаблоны
`html/template`), без React. Вход — HTTP Basic Auth: браузер сам спросит логин (`admin`) и пароль
(`ADMIN_PASSWORD` из `.env`; без пароля админка выключена). Неверный пароль отвечает с задержкой —
подбор дороже. Формы защищены от подделки запросов со сторонних сайтов (`http.CrossOriginProtection`).

- **Список** — «В работе» (новые, ждём аванс, аванс получен, печать, доставка), по статусам, все.
- **Карточка** — данные клиента (телефон звонится по нажатию, ссылка в WhatsApp), шаблон, превью книги,
  отправлено ли сообщение в Telegram, печатный PDF (появится на шаге 8).
- **Статус** — кнопка «Следующий шаг» или любой другой статус, с заметкой; всё попадает в историю.
  Клиент видит статус на своей странице заявки. **Отмена** снова открывает книгу для изменений;
  вернуть отменённую заявку нельзя, если клиент уже оформил новую.

На сервере пароль нужен длинный (`openssl rand -base64 18`), а админка — только по HTTPS (шаг 10).

### Печатный PDF

После заявки фоновая очередь (`backend/internal/render`) собирает печатный PDF. Как именно — настройка
формата в таблице `formats`, а не код:

| Настройка | По умолчанию | Что значит |
|---|---|---|
| `pdf_mode` | `single` | `single` — один файл `orders/<номер>/book.pdf`; `split` — `cover.pdf` (обложки) и `block.pdf` (страницы) |
| `pdf_order` | `front,pages,back` | порядок частей: `front` — передняя обложка, `pages` — страницы, `back` — задняя обложка |

Переключить, когда типография попросит иначе (потом в админке заявки — «Пересобрать PDF»):

```sql
-- make psql
UPDATE formats SET pdf_mode = 'split' WHERE id = 'square-200';
UPDATE formats SET pdf_order = 'back,pages,front' WHERE id = 'square-200';
```

Неверное значение база не примет; сервер ещё и проверяет настройку при старте.

- **Как:** сервис `render` (Node + Playwright, `render/server.mjs`) открывает печатную страницу сайта
  `/print/<id заявки>` — тот же компонент страницы, что в редакторе и превью, только с оригиналами фото —
  и печатает её в PDF. Ссылка подписана backend'ом (HMAC, 15 минут): без подписи оригиналы не отдаются.
- **Размер листа** — из таблицы `formats`: страница + вылет с каждой стороны (сейчас 206×206 мм);
  у обложек ещё и загиб `wrap_mm` (сейчас 0 — обложка того же размера). Корешок `spine_mm` пока не участвует.
- **Задняя обложка** — отдельная страница книги: в редакторе последняя, в превью последний «разворот».
  По умолчанию пустая с фоном передней обложки; клиент может добавить на неё текст, шаблон — задать дизайн.
- **Фото** вкладываются оригиналами без пересжатия. Фото «лёжа» с пометкой EXIF при загрузке получают
  повёрнутую печатную копию (libvips, качество 95) — иначе Chromium разжал бы их до десятков МБ.
- **Память:** каждый лист печатается отдельно и листы склеиваются `qpdf` без пересжатия — в памяти Chromium
  только фото одного листа; контейнеру дано 1,5 ГБ. Книга со 136 МБ фото — пик около 0,9 ГБ, около минуты.
- **Проверка результата** (pdfinfo, pdffonts, pdfimages): число страниц и размер каждой — как в плане,
  все шрифты встроены — иначе ошибка и до 3 попыток. Итог виден в админке, там же «Пересобрать PDF».
- **CMYK:** `PDF_CMYK=true` в `.env` → `make up` — PDF переводится в CMYK через Ghostscript (фото при этом
  пересжимаются в JPEG с качеством 95). Сейчас выключено: типографии нужен RGB.

### Telegram

О каждой заявке бот пишет в наш чат: номер, имя, телефон, адрес, дата, комментарий, ссылка на превью.
Сообщения уходят через очередь в базе (`orders.notified_at`): если Telegram недоступен, backend
повторит отправку позже. Без токена (по умолчанию) текст сообщения просто пишется в лог.

Как подключить:

1. В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → имя бота. Он пришлёт токен
   вида `123456789:AA…`.
2. Создайте группу для заявок (или используйте личный чат) и добавьте туда бота.
3. Напишите в группе `/start@имя_бота`, затем откройте в браузере
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id":-100…}` — это id чата.
4. В `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   TELEGRAM_CHAT_ID=-1001234567890
   ```
   и `make up`. Токен — секрет: только в `.env`, не в git.
5. Оформите тестовую заявку. Не пришло — `make logs` (строка `order notification failed` с ответом
   Telegram) или `make psql`: `select number, notify_attempts, notify_error from orders;`.

### Шрифты

Файлы — в `frontend/public/fonts/` (отдаёт наш сайт, внешних CDN нет: иначе PDF на сервере может
отрисоваться другим шрифтом), лицензии — рядом в `licenses/`. Список — `frontend/src/book/fonts.json`:
его читают и фронтенд (подключение `@font-face`, выбор шрифта), и backend (шаблон или книга со
шрифтом не из списка не принимаются). Все шрифты — SIL Open Font License 1.1.

Шрифты с Reserved Font Name в лицензии (Lobster, Lora, Marck Script, Playfair Display, PT Serif,
Raleway) лежат исходными `.ttf` без изменений: изменённую версию OFL разрешает распространять только
под другим именем. Остальные облегчены до латиницы и кириллицы и сохранены в woff2.
Добавить шрифт — скилл `add-font` и скрипт `tools/fonts/process_fonts.py`.

| Шрифт | Тип | Жирный | Казахские буквы |
|---|---|---|---|
| Caveat | рукописный | есть | есть |
| Marck Script | рукописный | нет | **нет** |
| Pacifico | рукописный | нет | есть |
| Lobster | рукописный | нет | есть |
| Playfair Display | с засечками | есть | есть |
| Lora | с засечками | есть | есть |
| PT Serif | с засечками | есть | есть |
| Montserrat | без засечек | есть | есть |

### Миниатюры

Фоновый обработчик в backend берёт из базы фото без миниатюры и вызывает `vipsthumbnail` (libvips):
1600 px по длинной стороне, поворот по EXIF, JPEG без метаданных, прозрачное — белым. По одному фото
за раз, чтобы память была предсказуемой. Битый файл пробуется 3 раза, причина — в `assets.thumb_error`.
libvips есть в Docker-образе; при локальном `go run` без него миниатюры не делаются (в логе предупреждение),
показываются оригиналы. Загрузки, которые начали, но не подтвердили, удаляются через сутки.

### Миграции

Файлы лежат в `backend/migrations/`, применяются автоматически при старте сервера
([goose](https://github.com/pressly/goose)). Новая миграция — новый файл со следующим номером:

```sql
-- backend/migrations/00006_orders.sql
-- +goose Up
CREATE TABLE orders (...);

-- +goose Down
DROP TABLE orders;
```

Ручное управление: `make migrate-status`, `make migrate-up`, `make migrate-down` (откат последней).

### Сбросить данные

```bash
docker compose down -v   # ВНИМАНИЕ: удаляет базу и все загруженные файлы
```

## Настройки (переменные окружения backend)
