# Photobook

Сервис подарочных фотокниг. Описание продукта, правила и план работ — в [CLAUDE.md](CLAUDE.md).

Готово:
- **шаг 1 — каркас**: Go-бэкенд, React-фронтенд, PostgreSQL, S3-хранилище, миграции, health-check;
- **шаг 2 — книга и шаблоны**: каталог шаблонов → просмотр шаблона → создание книги → книга по секретной ссылке `/b/<токен>`;
- **шаг 3 — редактор v0**: фото в слот (загрузка прямо в хранилище), сдвиг и масштаб кадра пальцем/мышью,
  автосохранение с черновиком на устройстве и защитой от затирания правок из другой вкладки;
- **шаг 4 — миниатюры и DPI**: миниатюры в фоне (libvips, с поворотом по EXIF), в редакторе — только они;
  предупреждение «Фото маленькое» на слоте, если для печати не хватает пикселей; уборка брошенных загрузок;
- **шаг 5 — превью**: книга по разворотам как после печати (с вылетами, без пустых рамок), линия реза
  и безопасная зона, сводка «что поправить» со ссылками на страницы в редакторе.

## Что нужно

- Docker с Docker Compose v2
- Для запуска без Docker и для `make test`: Go 1.27+ и Node.js 20.19+ (или 22.12+)

> Если у вас Go старее (например, 1.22), команды `go` в папке `backend/` сами скачают
> нужную версию (механизм `GOTOOLCHAIN`). Но лучше обновить Go: 1.22 уже не получает
> исправлений безопасности.

## Запуск

```bash
make up        # первый раз создаст .env из .env.example, соберёт и запустит всё
make ps        # статус сервисов: postgres, s3, backend должны быть (healthy)
make logs      # логи (Ctrl+C — выйти)
make down      # остановить; данные БД и файлов сохраняются в docker volumes
```

Без `make`: `cp .env.example .env && docker compose up --build -d`.

## Как проверить, что всё работает

| Что | Где | Ожидаемо |
|---|---|---|
| Каталог | http://localhost:5173 | три шаблона с обложками |
| Создание книги | открыть шаблон → «Создать книгу по этому шаблону» | адрес вида `/b/ABCD…` (26 символов), ссылка и кнопка «Копировать» |
| Возврат к книге | снова открыть http://localhost:5173 | плашка «Продолжить мою книгу» |
| Фото в слот | в книге тап по пустой рамке → выбрать фото | превью сразу, полоска загрузки, затем рамка выделена |
| Кадр | тянуть фото пальцем/мышью, ползунок «Масштаб», щипок, колесо | фото двигается за указателем, пустых полей не остаётся |
| Автосохранение | вверху справа | «Сохраняем…» → «Сохранено»; после обновления страницы всё на месте |
| Миниатюры | `make psql`: `select thumb_key, width_px, height_px from assets;` | у загруженных фото есть `thumb_key` (появляется через секунду-две) |
| Разрешение | фото меньше ~1600 px на страницу целиком, или сильное увеличение | плашка «Фото маленькое» на фото, пояснение внизу, точка на миниатюре страницы |
| Превью | в редакторе кнопка «Превью» | обложка, затем развороты [_ 1], [2 3] … [20 _]; пунктир реза и безопасной зоны; листание кнопками, стрелками, свайпом |
| Всё сразу в браузере | `make e2e` | `ALL CHECKS PASSED` (сценарий в [e2e/editor.mjs](e2e/editor.mjs)) |
| API | `curl localhost:8080/api/health` | `{"status":"ok","checks":{"db":"ok","storage":"ok"}}` |
| Консоль хранилища | http://localhost:9001/rustfs/console/ | вход по `S3_ACCESS_KEY` / `S3_SECRET_KEY` из `.env`, виден бакет `photobook` |
| База | `make psql`, затем `\dt` | таблицы `books`, `formats`, `goose_db_version` |
| Миграции | `make migrate-status` | все миграции `applied` |

Если зависимость недоступна, `/api/health` отвечает `503` и пишет, какая именно (`"storage":"error"`).

## Сервисы

| Сервис | Порт (только localhost) | Что это |
|---|---|---|
| `frontend` | 5173 | Vite dev-сервер, hot reload. `/api/*` проксирует на backend |
| `backend` | 8080 | Go API. При старте применяет миграции и создаёт бакет |
| `postgres` | 5432 | PostgreSQL 18 |
| `s3` | 9000 (API), 9001 (консоль) | [RustFS](https://github.com/rustfs/rustfs) — S3-совместимое хранилище |

Порты меняются в `.env`, если заняты.

### Проверка с телефона (в той же Wi-Fi сети)

По умолчанию сервисы доступны только с этого компьютера. Чтобы открыть сайт с телефона:

1. Узнайте IP компьютера в сети: `hostname -I` (первый адрес, например `192.168.0.109`).
2. В `.env` раскомментируйте и заполните:
   ```
   BIND_ADDR=0.0.0.0
   PUBLIC_HOST=192.168.0.109
   ```
3. `make up`, затем на телефоне откройте `http://192.168.0.109:5173`.

Сайт и хранилище фото станут видны всем в этой сети — в общественном Wi-Fi так не делайте.
Кнопка «Копировать» ссылку без HTTPS на телефоне может не сработать — ссылку можно выделить вручную.
Вернуть как было — закомментировать строки обратно и снова `make up`.

**Почему RustFS, а не MinIO:** MinIO с 2025 года не публикует бесплатные Docker-образы.
Бэкенд работает с хранилищем только по протоколу S3, поэтому RustFS можно заменить
на любой другой S3 (SeaweedFS, облачный S3) правкой сервиса `s3` в `docker-compose.yml`.

## Разработка

**Frontend** — правки в `frontend/src` сразу видны в браузере.
Если поменяли `package.json`: `docker compose restart frontend`.

**Backend и шаблоны** — после правок пересобрать: `docker compose up --build -d backend`.
Или запустить локально против Postgres и S3 из Docker:

```bash
cd backend
export DATABASE_URL="postgres://photobook:photobook@localhost:5432/photobook?sslmode=disable"
export S3_ENDPOINT=localhost:9000 S3_ACCESS_KEY=photobook S3_SECRET_KEY=photobooksecret S3_BUCKET=photobook
export HTTP_ADDR=:8081   # 8080 занят контейнером backend
# TEMPLATES_DIR по умолчанию ../templates — для запуска из backend/ ничего задавать не нужно
go run ./cmd/server
```

**Тесты:** `make test` (Go-тесты, юнит-тесты фронтенда на vitest — кадр и DPI, линтер, сборка; один раз перед этим `cd frontend && npm install`).

**Сквозной тест в браузере:** `make e2e` — Chromium (Playwright в Docker) проходит путь клиента: создаёт книгу,
загружает фото с EXIF-поворотом, двигает и увеличивает кадр, проверяет автосохранение, обрыв сети,
конфликт двух вкладок. Скриншоты — в `e2e/shots/`. Первый запуск скачает образ ~3.6 ГБ.

### Шаблоны

Лежат в [templates/](templates/), один JSON-файл = один шаблон. Формат и правила — в
[templates/README.md](templates/README.md). Сервер проверяет все шаблоны при старте и не
запустится с битым файлом; `make test` проверяет их без запуска.

### API

| Метод и путь | Что делает |
|---|---|
| `GET /api/health` | состояние сервиса и зависимостей |
| `GET /api/templates` | каталог: шаблоны без внутренних страниц, но с обложкой и форматом |
| `GET /api/templates/{id}` | шаблон целиком |
| `POST /api/books` `{"templateId": "…"}` | создать книгу по шаблону → `201 {"token": "…"}` |
| `GET /api/books/{token}` | книга (обложка, страницы, `version`) с форматом и списком фото |
| `PUT /api/books/{token}` `{"version", "cover", "pages"}` | автосохранение; `409 version_conflict`, если книгу уже сохранили из другой вкладки |
| `POST /api/books/{token}/assets` `{"contentType", "size"}` | начать загрузку фото → `{"assetId", "uploadUrl"}` |
| `PUT <uploadUrl>` | браузер кладёт файл прямо в хранилище (presigned URL, 15 минут) |
| `POST /api/books/{token}/assets/{id}/complete` `{"width", "height"}` | подтвердить загрузку; сервер проверяет файл |
| `GET /api/books/{token}/assets/{id}/image` | редирект на временную ссылку миниатюры (пока она готовится — оригинала) |

Ошибки приходят как `{"error": "код"}` (`book_not_found`, `unsupported_type`, `file_too_large`,
`bad_image`, `version_conflict`, …); текст для человека фронтенд берёт из словаря по коду.

### Миниатюры

Фоновый обработчик в backend берёт из базы фото без миниатюры и вызывает `vipsthumbnail` (libvips):
1600 px по длинной стороне, поворот по EXIF, JPEG без метаданных, прозрачное — белым. По одному фото
за раз, чтобы память была предсказуемой. Битый файл пробуется 3 раза, причина — в `assets.thumb_error`.
libvips есть в Docker-образе; при локальном `go run` без него миниатюры не делаются (в логе предупреждение),
показываются оригиналы. Загрузки, которые начали, но не подтвердили, удаляются через сутки.

### Миграции

Файлы лежат в `backend/migrations/`, применяются автоматически при старте сервера
([goose](https://github.com/pressly/goose)). Новая миграция — новый файл со следующим номером:

```sql
-- backend/migrations/00006_orders.sql
-- +goose Up
CREATE TABLE orders (...);

-- +goose Down
DROP TABLE orders;
```

Ручное управление: `make migrate-status`, `make migrate-up`, `make migrate-down` (откат последней).

### Сбросить данные

```bash
docker compose down -v   # ВНИМАНИЕ: удаляет базу и все загруженные файлы
```

## Настройки (переменные окружения backend)

| Переменная | Пример | |
|---|---|---|
| `HTTP_ADDR` | `:8080` | адрес HTTP-сервера (по умолчанию `:8080`) |
| `DATABASE_URL` | `postgres://user:pass@host:5432/db?sslmode=disable` | обязательна |
| `S3_ENDPOINT` | `s3:9000` | host:port без схемы, обязательна |
| `S3_ACCESS_KEY`, `S3_SECRET_KEY` | | обязательны |
| `S3_BUCKET` | `photobook` | создаётся при старте, если нет |
| `S3_USE_SSL` | `false` | `true` для HTTPS-хранилища |
| `S3_REGION` | `us-east-1` | регион для подписи ссылок |
| `S3_PUBLIC_ENDPOINT` | `localhost:9000` | адрес хранилища для браузера: на него указывают ссылки загрузки и просмотра фото (по умолчанию = `S3_ENDPOINT`) |
| `S3_PUBLIC_USE_SSL` | `false` | по умолчанию = `S3_USE_SSL` |
| `APP_ORIGINS` | `http://localhost:5173` | адреса сайта через запятую; им хранилище разрешает загрузку из браузера (CORS) |
| `TEMPLATES_DIR` | `/app/templates` | папка шаблонов (по умолчанию `../templates`) |
