# Photobook — сервис подарочных фотокниг (Казахстан, Алматы)

## Что это
Сайт, где клиент собирает фотокнигу из готовых шаблонов (обложка + развороты, фото, текст, стикеры), видит превью и оставляет заявку. Мы получаем заявку в Telegram, скачиваем печатный PDF, печатаем в типографии, доставляем сами (Алматы). Оплата на старте: ручное подтверждение аванса переводом.

Владелец проекта — backend-разработчик (Go, Python, Docker), опыта с фронтендом мало. Поэтому:
- комментируй нетривиальные решения на фронтенде коротко и по делу;
- выбирай простые и проверенные подходы, не изобретай;
- сначала сквозной путь (шаблон → заполнение → превью → заявка), потом украшения.

## Стек (не менять без обсуждения)
- Backend: Go, один модульный монолит (без микросервисов и k8s)
- Frontend: React + TypeScript + Vite, **mobile-first** (клиенты и с телефона, и с компьютера)
- БД: PostgreSQL (книга хранится как JSONB)
- Файлы: S3-совместимое хранилище, RustFS локально и на старте на сервере. MinIO с 2025 года не публикует бесплатные образы, поэтому 2026-10-17 заменён на RustFS. Код работает только через протокол S3 (клиент minio-go), без привязки к конкретному хранилищу.
- PDF: headless Chromium (Playwright) рендерит ту же страницу, что видит клиент
- Миниатюры: libvips (с поддержкой HEIF — `vips-heif`, `libheif-libde265` в образе backend)
- Уведомления: Telegram-бот
- Инфраструктура: один VPS, Docker Compose, Caddy (HTTPS), GitHub Actions

## Формат книги (настройка, НЕ константа)
Таблица `formats`. Значения по умолчанию для разработки (потом заменить на данные типографии):
- размер страницы: 200 × 200 мм
- страниц в книге: **16, фиксированно** (первая версия сервиса, решение 2026-10-22; обложки отдельно; столько страниц в шаблонах). Механизм изменения числа страниц остался: `min_pages = max_pages = 16`, шаг 2 — вернуть выбор = поменять цифры в `formats` (миграция `00014`)
- доплата за страницу сверх 20: 0 ₸ (`price_per_page_kzt`)
- вылет (bleed): 3 мм
- безопасная зона: 5 мм от края реза
- минимальное разрешение фото в слоте: 200 DPI (предупреждение), цель 300 DPI

Любой код, который зависит от размеров, читает их из формата, а не из констант.

## Модули backend
- `books` — книга, страницы (JSON), автосохранение, секретная ссылка (токен), без регистрации
- `assets` — загрузка фото напрямую в хранилище (presigned URL), миниатюры в фоне, проверка разрешения, лоток «Мои фото» (удаление из лотка и «Отменить»)
- `templates` — шаблоны (пока файлы JSON в репозитории); наборы стикеров — `stickers` (SVG во `frontend/public/stickers`, список в `frontend/src/book/stickers.json`)
- `orders` — заявка, контакты, статусы, история статусов, окно правок после заявки, снимки заказа (версии)
- `render` — очередь и сборка печатного PDF (по одному за раз, только после заказа)
- `notify` — Telegram-бот: новая заявка, «клиент изменил книгу», ссылка в админку
- `admin` — простая страница под паролем: список заказов, смена статуса, «Отправить в печать», правка текстов по просьбе клиента, версии заказа и их PDF

## Модель данных
- `formats` (id, name, width_mm, height_mm, bleed_mm, safe_mm, pages, min_pages, max_pages, page_step, min_dpi, target_dpi, price_kzt, price_per_page_kzt, spine_mm, wrap_mm, created_at). `pages` — страниц у новой книги (столько в шаблонах); `min_pages`…`max_pages` — пределы, число страниц кратно `page_step` (проверяют база, сервер при старте и при каждом сохранении книги). `price_kzt` — цена книги с `pages` страниц; цена книги = `price_kzt` + `price_per_page_kzt` × (страниц − `pages`), не меньше 0 (`formats.Format.Price` на сервере, `bookPrice` на фронтенде). `spine_mm` — корешок, `wrap_mm` — загиб обложки на картон (оба 0, пока типография не даст цифры). `pdf_mode` — `single` (по умолчанию, один book.pdf) или `split` (cover.pdf + block.pdf); `pdf_order` — порядок частей PDF, по умолчанию `front,pages,back`. `id` — читаемый slug (`square-200`), на него ссылаются шаблоны; `price_kzt` — целое число в тенге
- `books` (id, token, format_id, template_id, schema_version, version, cover JSONB, pages JSONB, back_cover JSONB, created_at, updated_at). `back_cover` — задняя обложка (страница; по умолчанию пустая с фоном передней). `version` растёт при каждом сохранении; автосохранение присылает версию, которую видело, и получает 409 при конфликте. `cover` — страница обложки, `pages` — массив внутренних страниц (см. «Формат страницы»), `schema_version` — версия этого формата JSON. `token` — 26 символов base32 (`crypto/rand.Text`)
- `assets` (id, book_id, status pending|uploaded, original_key, thumb_key, print_key, content_type, width_px, height_px, size_bytes, sha256, taken_at, removed_at, created_at, uploaded_at, thumb_attempts, thumb_error). `print_key` — печатная JPEG-копия: для фото с пометкой EXIF о повороте и для любого HEIC. Размеры — с учётом поворота EXIF, как фото видит человек; после миниатюры их уточняет сервер. `sha256` — хеш файла (от браузера, против повторов), `taken_at` — дата съёмки EXIF DateTimeOriginal (местное время камеры, без пояса), `removed_at` — удалено из лотка (файл остаётся). Порядок загрузки — `created_at`
- `orders` (id, number, book_id, book_version, name, phone, address, wanted_date, status, comment, price_kzt, confirmed_at, book_changed_at, change_settled_at, book_pdf_key, cover_pdf_key, block_pdf_key, pdf_book_version, render_reason, render_requested_at, render_attempts, render_error, rendered_at, pdf_info, notified_at, notify_attempts, notify_error, created_at, updated_at). `number` — номер для людей с 1001; `phone` — `+7XXXXXXXXXX`; `book_version` и `price_kzt` — на момент заявки; `confirmed_at` — галочка «проверил(а)»; `book_changed_at`/`change_settled_at` — правки клиента после заявки и до какой из них всё обработано; `*_pdf_key` + `pdf_book_version` — текущий PDF и версия книги, из которой он собран; `rendered_at` пусто — PDF ждёт сборки; `notified_*` — очередь уведомлений о новой заявке в Telegram
- `order_events` (id, order_id, status, note, created_at)
- `order_versions` (id, order_id, version, reason order|client_change|admin_change|rerender, book_version, template_id, template_version, schema_version, format JSONB, cover/pages/back_cover JSONB, confirmed_at, created_at, book_pdf_key, cover_pdf_key, block_pdf_key, pdf_info, rendered_at) — снимки заказа, см. «Заявка: проверка, окно правок, снимки»
- `order_notices` (id, order_id, kind book_changed, book_version, created_at, sent_at, attempts, error) — очередь сообщений в Telegram об изменениях книги

Одна неотменённая заявка на книгу (уникальный индекс). Книга **закрыта для изменений**, только когда заказ в печати (`printing`, `delivery`, `done`); до этого её можно менять (окно правок, см. ниже). Самая ранняя желаемая дата — сегодня по Алматы (UTC+5) + `ORDER_MIN_LEAD_DAYS` (по умолчанию 3).

Статусы заказа: `new → awaiting_prepayment → paid → printing → delivery → done` (+ `cancelled`).

## Формат страницы (JSON, единый источник правды)
Страница = список элементов. Один и тот же JSON рендерится в редакторе, в превью и в PDF.

```json
{
  "pages": [
    {
      "id": "p1",
      "background": "#ffffff",
      "elements": [
        { "type": "photo_slot", "id": "s1", "x": 0, "y": 0, "w": 100, "h": 100,
          "assetId": null, "crop": { "zoom": 1, "offsetX": 0, "offsetY": 0 } },
        { "type": "text", "id": "t1", "x": 10, "y": 80, "w": 80, "h": 15,
          "text": "", "font": "playfair-display", "size": 14, "align": "center", "rotation": 0 },
        { "type": "sticker", "id": "st1", "x": 50, "y": 10, "w": 20, "h": 20,
          "stickerId": "love-heart", "rotation": 0 }
      ]
    }
  ]
}
```
Координаты в процентах от страницы (0–100), чтобы одинаково работало на любом экране и в PDF. Блок `text` клиент двигает свободно, и он может частично выходить за страницу (`x < 0`, `x + w > 100`): что за линией реза — обрежется; хотя бы часть блока остаётся на странице (backend требует пересечения, редактор держит на странице четверть ширины и высоты блока). Фото-слоты и стикеры — целиком на странице.
- Ключи JSON — camelCase везде (страницы, шаблоны, ответы API).
- `size` текста — кегль в пунктах на напечатанной странице; на экране переводится в `cqw` (доля ширины страницы): px = мм × ширина страницы на экране / `width_mm`. Поэтому кегль одинаков относительно страницы на телефоне, компьютере, в превью и PDF (проверка — `e2e/text-move.mjs`).
- `rotation` у `text` и `sticker` — градусы по часовой вокруг центра блока, −180…180, нет поля — 0. Рисуется CSS `transform: rotate` в `PageView`, на вёрстку и подбор кегля не влияет. Положение и наклон в PDF совпадают с редактором — проверка по пикселям в `e2e/print.mjs` (шаг 5б).
- `font` — id шрифта в kebab-case (`playfair-display`, `caveat`).
- `crop` фото: фото вписывается в слот с заполнением (как `object-fit: cover`), затем `zoom` (1–4); `offsetX`/`offsetY` от −1 до 1 выбирают видимую часть (−1 левый/верхний край, 0 центр, 1 правый/нижний). Рендер — чистый CSS (`object-position` + `transform: scale` с тем же `transform-origin`), без пикселей. Код: `frontend/src/book/crop.ts`.
- **Вылет:** фото-слот, прижатый к краю страницы (x = 0, y = 0, x + w = 100 или y + h = 100), рендерится с запасом `bleed_mm` за линией реза с этой стороны; остальные элементы — нет. `PageView` всегда рисует лист с вылетом, а наружу показывает либо страницу по линии реза (редактор), либо лист целиком (`showBleed` — превью, PDF), поэтому кадр в редакторе = кадр на печати. Код: `frontend/src/book/geometry.ts`.
- `PageView variant="print"` (превью, PDF): пустые рамки не печатаются, виден фон страницы.
- **Узор фона:** `backgroundImage` страницы — id из `frontend/src/book/backgrounds.json` (общий конфиг с backend, как стикеры; SVG во `frontend/public/backgrounds`, рисует `tools/backgrounds/generate.py`): поверх цвета `background`, на весь лист с вылетом, в PDF — вектор. Узоры без фильтров (тени — полупрозрачными фигурами), иначе Chromium растрирует их при печати.
- **Форма фото-рамки:** `shape: "heart"` у `photo_slot` — сердце векторным `clip-path: polygon()` (`frontend/src/book/shapes.ts`); не CSS-маска: маска в PDF растрируется и оставляет волосок по краю рамки. Фото внутри кадрируется как обычно, в PDF остаётся JPEG.
- **Фото поверх фото:** в шаблоне фото не наезжает на фото, кроме «вставки» — фото целиком внутри другого (снимок с каймой поверх большого фото). Сверху то, что позже в списке элементов.
- **Стикер:** `stickerId` — id из `frontend/src/book/stickers.json` (общий конфиг фронтенда и backend, как шрифты), `rotation` — градусы по часовой, −180…180, вокруг центра. Рисунок — SVG, вписан в блок без искажений; высоту блока редактор считает по пропорциям рисунка (`aspect`) и формата. Блок целиком на странице (поворот может вывести углы за край — уходят в вылет). В PDF остаётся вектором. Удалять стикер из конфига нельзя, пока он есть в шаблонах и книгах.
- Go-модель и проверка: `backend/internal/pages`, TS-типы: `frontend/src/types.ts`, отрисовка: `frontend/src/book/PageView.tsx`.

## Текст и шрифты
Клиент сам пишет текст на странице и выбирает шрифт.
- Элемент `text`: тап по тексту → ввод; настройки: шрифт, размер, цвет, выравнивание, жирность. Поле ввода — с проверкой орфографии браузера (`spellCheck`, `lang="ru"`: опечатки подчёркиваются красным).
- Шрифты: Google Fonts с **кириллицей**, **хранить файлами на нашем сервере** (self-host, формат woff2), а не подключать с внешнего CDN. Иначе в PDF на сервере шрифт может не загрузиться и печать отличится от превью.
- Набор на старте 10–12 шрифтов: 3–4 рукописных/каллиграфических (Caveat, Marck Script, Pacifico, Lobster), 3–4 классических с засечками (Playfair Display, Lora, PT Serif), 3–4 простых без засечек (Montserrat, Raleway, Nunito). Проверить, что все поддерживают кириллицу.
- Конфиг шрифтов лежит в одном файле (список: id, название, файл), чтобы добавлять новые без изменений кода. Это `frontend/src/book/fonts.json` (его читает и backend для проверки), файлы — `frontend/public/fonts/`, лицензии — `frontend/public/fonts/licenses/`. Шрифты с Reserved Font Name в OFL храним исходными `.ttf` без изменений; остальные — облегчённые woff2 (`tools/fonts/process_fonts.py`, скилл `add-font`).
- PDF-рендер должен ждать загрузки шрифтов (`document.fonts.ready`) перед печатью.
- Текст не должен выходить за безопасную зону: показывать предупреждение. Сделано мягко (не запрет): «Близко к краю» на блоке и пояснение в панели, если блок с учётом поворота ближе `formats.safe_mm` к линии реза (`nearCutLine` в `frontend/src/editor/transform.ts`).
- Длинный текст переносится внутри блока, размер можно уменьшить автоматически (auto-fit) до минимума. Сделано в `PageView` (TextView): самый крупный кегль ≤ заданного, при котором текст влезает, но не меньше 8 пт; не влезает и так — в редакторе «Не помещается». В шаблонах безопасная зона для текста проверяется строго (backend, с учётом поворота); у клиента — только предупреждение.
- Свой текст клиент добавляет кнопкой «Добавить текст»: блок внизу страницы на всю ширину безопасной зоны, id с префиксом `ut-`. Любой текстовый блок (и из шаблона — шаблон при этом не меняется, книга его копия) клиент свободно двигает, меняет размер и поворачивает: тап — выбор (рамка и ручки, зона касания 44px), повторный тап или двойной клик — ввод текста, перетаскивание ввод не открывает; привязка к центру и краям страницы с направляющими; «Копия», «Вперёд», «Удалить»; «Отменить» / «Повторить» (Ctrl+Z / Ctrl+Shift+Z) — для всех правок, жест — один шаг. Жесты — Pointer Events без библиотек (`frontend/src/editor/TextOverlay.tsx`), геометрия в мм — `transform.ts`, история — `autosave.ts`. Во время жеста запросов нет: автосохранение уходит через 1,5 с после последней правки. Ограничения backend: шрифт из конфига, жирный — только если есть такое начертание, до 1000 символов в блоке, до 50 элементов на странице.
- Проверка шрифтов в PDF (`pdffonts`) — на шаге 8, когда появится рендер.

- Книга при создании копирует страницы шаблона и дальше живет независимо (изменение шаблона не меняет чужие книги).

## Заявка: проверка, окно правок, снимки
Защита клиента и нас от опечаток и от «печатаем не то». Правила — не ослаблять.
- **Проверка перед заявкой** (`/b/<токен>/order`, `screens/BookReview.tsx`): шаг «Проверьте книгу» — клиент листает все страницы по порядку (обложка → страницы → задняя обложка) и на каждой видит подписи, пустые рамки, маленькие фото, текст у края и «не помещается». Внизу обязательная галочка «Я проверил(а) тексты и фото. После печати исправить ничего нельзя» — поставить можно, только пролистав до конца. Без галочки кнопка выключена, а сервер отвечает 400 `not_confirmed` (`orders.Input.Confirmed`). Экран «Все подписи книги» — `/b/<токен>/texts` (`screens/TextsScreen.tsx`): тексты по страницам со ссылкой на страницу в редакторе.
- **Окно правок:** пока заказ `new`, `awaiting_prepayment` или `paid` (`orders.Editable`, `lib/orderStatus.ts`), книга открывается в редакторе по секретной ссылке, с пояснением про заявку. С `printing` и дальше (`orders.Locked`) — только просмотр (`editor/ReadOnlyBook.tsx`): «Книга уже в печати, изменить её нельзя». Автосохранение и загрузка фото получают 409 `book_locked`.
- **Блокировка без потери данных:** `books.SavePages` сначала блокирует строку заказа (`FOR UPDATE`), «Отправить в печать» (`orders.ChangeStatus` → `printing`) — её же; поэтому правка и печать не пересекаются. Отклонённая правка ничего не записывает; черновик клиента в localStorage при блокировке не удаляется (пригодится, если заказ отменят), а показывается то, что на сервере.
- **Правки клиента после заявки:** каждое сохранение отмечает `orders.book_changed_at`, «PDF устарел» в админке виден сразу. Когда клиент не правил `ORDER_CHANGE_QUIET_SECONDS` (60 с) — `orders.RunChanges` один раз: запись в `order_events` («Клиент изменил книгу»), сообщение в Telegram «Клиент изменил книгу в заказе №N» (очередь `order_notices`), пересборка PDF (новая версия). Не на каждое автосохранение.
- **«Отправить в печать»** (админка) — только когда PDF собран из текущей версии книги (`Row.PDFCurrent`: `rendered_at` есть и `pdf_book_version = books.version`); иначе кнопка выключена, а сервер отвечает ошибкой. После неё книга закрыта.
- **Правка администратором:** «Поправить тексты по просьбе клиента» (`/admin/orders/N/texts`, пока заказ в окне правок) — тексты всех блоков; сохранение пишет «Изменено администратором: текст — стр. N» в историю и сразу ставит пересборку.
- **Снимки заказа** (`order_versions`, `orders/versions.go`): при заявке (v1, с подтверждением клиента) и при каждой пересборке PDF — новая запись: копия страниц, формат целиком, шаблон и его версия (`templates.Template.Version` — хеш файла), дата, подтверждение. **Печатается снимок**, а не живая книга (`/print/<заказ>?v=N`, подпись ссылки включает версию), поэтому PDF версии всегда соответствует её содержимому. Файлы — `orders/<номер>/v<версия>/…`, ссылка на PDF хранится у версии. Снимки не меняются и не удаляются — это охраняет триггер в базе; PDF версии пишется один раз. В админке — «Версии заказа» с PDF каждой версии.
- Просьба о пересборке во время сборки не теряется: `render_requested_at` позже снимка — заявка остаётся в очереди.
- Проверки: `make test-db` (Go на настоящей базе: без галочки нет заявки; правка в `new` → событие, Telegram, пересборка; в печать со старым PDF нельзя; с `printing` правка отклоняется и книга не меняется; снимки не перезаписываются), `e2e/order.mjs` (проверка книги, галочка, «Все подписи», правка после заявки, орфография), `e2e/order-window.mjs` (клиент правит после заявки → «PDF устарел» → Telegram и v2 → правка админом → v3 → «Отправить в печать» → только просмотр).
- **Цена** остаётся зафиксированной при заявке (`orders.price_kzt`), даже если клиент потом поменяет число страниц: при доплате за страницы — обсудить по телефону.

## Лоток фото и массовая загрузка
Фото загружаются в книгу пачкой и раскладываются по рамкам без повторной загрузки (по отзыву: раньше на каждую рамку открывали галерею заново).
- **Лоток «Мои фото»** = список `assets` книги (`book.assets`, `GET /api/books/{token}/assets`); рамка хранит только `assetId`, формат страницы не менялся. Одно фото может стоять в нескольких рамках. На телефоне — шторка снизу (кнопка «Мои фото · N» в панели), от 1100px — колонка справа под панелью настроек. Сверху «Использовано N из M фото», на миниатюре галочка (число — во скольких рамках) и «!» — маленькое фото: в режиме выбора — для этой рамки, у фото в книге — по его рамкам, у остальных — для рамки в пол-страницы. Код: `editor/PhotoTray.tsx`, чистые функции — `editor/tray.ts`.
- **Тап по пустой рамке открывает лоток, а не галерею.** Цели — эта рамка и остальные пустые рамки страницы по порядку; отмеченные фото (номер на миниатюре) встают в них в порядке выбора, кнопка «Вставить N фото». Одна рамка («Заменить», единственная пустая) — тап сразу ставит; фото, загруженное «Загрузить ещё» в режиме одной рамки, встаёт в неё само, при нескольких — отмечается. На компьютере миниатюру можно перетащить мышью в рамку (HTML Drag and Drop, `DRAG_TYPE`), заполненная рамка заменяется.
- **Массовая загрузка:** `<input type="file" multiple accept="image/*,.heic,.heif">`. Лимиты — `frontend/src/editor/uploads.json`, общий с backend (`UPLOADS_CONFIG`): `maxFileMb`, `maxPerBook`, `types` проверяют и фронтенд, и сервер; `maxFilesPerBatch` (лишние не грузятся, сообщение), `parallel` (3), `retries` (2) — только фронтенд. Очередь — `editor/uploadQueue.ts` (без React): по `parallel` файлов, сбой сети — повтор через 1,5 и 3 с, потом файл в списке ошибок с «Повторить»; ошибки формата/лимита не повторяются; один сбойный файл остальные не останавливает. Закрытие вкладки во время загрузки — `beforeunload`.
- **Повторы не загружаются:** сначала имя + размер + дата изменения файла (мгновенно), затем SHA-256 содержимого (`crypto.subtle`, только https/localhost) — с фото книги и с очередью; сервер тоже отвечает `duplicate` по `sha256`. Удалённое из лотка фото повтором не считается.
- **Локальное превью** — уменьшенная копия (до 1024 px, `localPreview`): 60 фото по 12 Мп в полном размере телефон не потянет. HEIC Chrome не открывает — тогда размеры даёт сервер (`vipsheader`), в лотке «Готовим фото…», редактор спрашивает список, пока не готова миниатюра (`viewable`), картинка отвечает 404 `not_ready`.
- **Автораскладка** «Разложить автоматически»: неиспользованные фото по порядку — по дате съёмки (`takenAt`, EXIF читает браузер в `editor/exif.ts`, для HEIC — сервер при миниатюре), фото без даты — после, в порядке загрузки — в пустые рамки по порядку страниц (обложка, страницы, задняя обложка). Заполненные рамки не трогает. «Разложено N фото» + «Отменить» (освобождает только рамки, где всё ещё стоит то же фото); не хватило рамок — говорим, сколько, ничего не удаляя. Это не «ИИ-автосборка»: просто по порядку.
- **Удаление из лотка:** фото в книге — сначала вопрос со списком страниц, рамки освобождаются; «Отменить» возвращает фото в лоток и в рамки. На сервере только пометка `removed_at` (`DELETE …/assets/{id}`, `POST …/restore`), файл остаётся; фото, на которое ссылается рамка (например, после Ctrl+Z), остаётся в лотке и печатается. Пока есть заявка — 409 `book_locked`.
- **HEIC:** libvips в образе собран с HEIF (`vips-heif`, `libheif-libde265`): оригинал хранится как есть, миниатюра — JPEG, для печати — JPEG-копия Q=98 без прореживания цвета (Chromium HEIC не печатает). Тестовые файлы — `e2e/fixtures/*.heic` (`make_heic.py`).
- **Заявка и админка** показывают, сколько фото загружено, но не стоит ни в одной рамке (не печатаются); пустые рамки — предупреждение, заказ не блокируется.
- Проверки: `tray.test.ts`, `uploadQueue.test.ts`, `exif.test.ts`, `e2e/tray.mjs` (20 файлов с одним сбойным, повторы, выбор, перетаскивание, автораскладка и отмена, удаление, HEIC в PDF, шторка на телефоне).

## Страницы книги (клиент меняет число)
**Сейчас выключено:** книга ровно 16 страниц (`min_pages = max_pages`) — кнопок «Удалить/Добавить» и плитки «+» нет (`PagesBar` и лента их не показывают), сервер принимает только 16 (и прежнее число страниц старых книг). Ниже — как работает, когда пределы снова разведут.
- В редакторе под страницей: «Удалить страницы 5–6», «Добавить 2 страницы» и счётчик «Страниц: 18 из 20» с подсказкой, сколько можно; в ленте миниатюр плитка «+» — лист в конец. Код: `frontend/src/editor/pages.ts` (чистые функции), `PagesBar.tsx`.
- Удаляются и добавляются **листами по `page_step`** (при шаге 2 — страницы 5 и 6 вместе: у листа две стороны). Так число страниц всегда кратно шагу — неправильной книги не бывает ни в автосохранении, ни в заявке, ни в PDF. Ниже `min_pages` и выше `max_pages` нельзя: кнопка выключена с причиной («Минимум 10 страниц»). Обложки не удаляются и не считаются.
- Пустой лист удаляется сразу; если на нём есть фото, текст или стикеры — сначала вопрос. После удаления — «Страницы 5–6 удалены» с «Отменить» (возвращает на то же место); общая «Отменить» (Ctrl+Z) тоже работает. Всё — через то же автосохранение.
- Новый лист — устройство соседнего листа без содержимого: тот же фон, пустые рамки, пустые подписи шаблона; стикеры и свой текст клиента не копируются. Добавляется после листа открытой страницы (с обложки — в начало, с задней обложки и из ленты — в конец).
- Сервер принимает число страниц в пределах формата и кратное шагу; прежнее число страниц книги — всегда (если формат потом поменяют, старые книги продолжат сохраняться).
- Заявка, Telegram, админка и печатный PDF берут фактическое число страниц книги (`jsonb_array_length(books.pages)`). Перед заявкой — предупреждение о пустых страницах со ссылками в редактор; заказ не блокируется.
- Фото удалённых страниц остаются в хранилище (поэтому работает «Отменить»). **Позже:** фоновая уборка фото, на которые не ссылается ни одна страница книги.

## Безопасность (минимум, сделано)
- **Ограничение частоты с одного IP** (`backend/internal/ratelimit`, лимиты — в `httpapi.New`): новые книги 20/ч, загрузки фото 600/ч, автосохранение 120/мин, заявки 5/ч (каждая — сообщение в Telegram), остальное 1200/мин; сверх — 429 `too_many_requests` (автосохранение просто повторит позже). Локальные и внутренние адреса не ограничиваются (разработка, тесты, `make share`); в бою адрес клиента берётся из `X-Forwarded-For`, который дописывает свой прокси (Caddy).
- **Админка:** Basic Auth со сравнением за постоянное время и паузой 0,5 с; 10 неверных паролей с адреса — вход закрыт (одна попытка возвращается раз в 1,5 мин); строгая CSP (скриптов нет).
- **Загрузка фото:** размер файла входит в подпись ссылки (`Content-Length`) — файл другого размера хранилище отклонит; при подтверждении — ещё проверка размера и картинки.
- **Заголовки:** `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin` на всех ответах API и админки. Для статики сайта — в Caddy при деплое.
- **Таймауты HTTP-сервера** (чтение 30 с, запись 60 с, простой 2 мин) против медленных соединений.
- **Боевой режим** `APP_ENV=production`: сервер не запустится с паролями из `.env.example`, с паролями базы, хранилища и админки короче 16 символов и без `https://` в `APP_BASE_URL`.
- Уже было: секретные токены книг (130 бит), подписанные ссылки на печать (HMAC, 1 ч), запросы к базе с параметрами, экранирование в админке и Telegram, лимит тела запроса 1 МБ, порты базы и хранилища только на 127.0.0.1.
- **При деплое:** наружу только 80/443 (Caddy, HTTPS), база, хранилище, backend и рендер — только во внутренней сети Docker; вход на сервер по SSH-ключу; секреты — в `.env` на сервере; бэкапы.

## Правила
1. **Превью = печать.** Один компонент рендерит страницу везде. Превью показывает линию реза и безопасную зону.
2. **Низкое разрешение — предупреждение** прямо на слоте («Фото маленькое, на печати будет нечетким»). Приоритет выше стикеров.
3. **Автосохранение** каждые несколько секунд + копия черновика в localStorage на случай обрыва сети.
4. **Клиент видит только миниатюры**, оригиналы хранятся для печати. Клиент PDF не скачивает.
5. **Загрузка фото с телефона** (5–10 МБ): грузим напрямую в хранилище, пачкой в лоток «Мои фото», локальное превью показываем сразу.
6. **PDF строится в фоне**, одна задача за раз, ограничение памяти у Chromium.
7. **Бэкапы:** ежедневный дамп БД + копия файлов.
8. Редактор должен нормально работать на телефоне (касания, без hover-зависимостей) и на компьютере.
9. Весь интерфейс на русском, строки выносить в словарь (позже добавим казахский).
10. Секреты только через переменные окружения.

## Порядок работы (milestones)
Каждый шаг заканчивается рабочей версией, которую можно запустить и проверить.

1. **Каркас:** репозиторий, Docker Compose (Go, Postgres, S3/RustFS, фронтенд), health-check, миграции.
2. **Книга и шаблоны:** создать книгу по токену, загрузить 2–3 тестовых шаблона, отдать их на фронтенд.
3. **Редактор v0:** выбор шаблона → тап по слоту → загрузка фото → подвинуть/масштабировать кадр внутри слота. Автосохранение. (Загрузка сразу сделана через presigned URL, чтобы не писать временный вариант.)
4. **Загрузка и миниатюры:** миниатюры в фоне (libvips, с поворотом по EXIF), клиенту отдавать миниатюры вместо оригиналов, проверка DPI и предупреждение, уборка незавершённых загрузок. libvips вызывается утилитой `vipsthumbnail` отдельным процессом (без CGO). DPI считает `frontend/src/book/dpi.ts`: `25.4 / (max(слот_мм_ш / фото_px_ш, слот_мм_в / фото_px_в) × zoom)`, предупреждение ниже `formats.min_dpi`.
5. **Превью:** листание по разворотам, линия реза и безопасная зона. Раскладка: обложка отдельно, затем [_ 1], [2 3] … [20 _] (`frontend/src/book/spreads.ts`) — **сверить с типографией**. Превью показывает несохранённые правки из черновика и сводку: пустые рамки, маленькие фото, со ссылками `/b/<токен>?page=N`.
5а. **Текст и шрифты:** добавление и редактирование текстовых блоков, выбор шрифта, размера, цвета и выравнивания (см. раздел «Текст и шрифты»). Проверка, что кириллица рисуется именно нашим файлом, — `e2e/text.mjs`.
6. **Заявка:** форма (имя, телефон, адрес, желаемая дата), создание заказа, сообщение в Telegram. Форма — `/b/<токен>/order` (из превью) с шагом «Проверьте книгу» и обязательной галочкой; перед заявкой несохранённый черновик дохраняется; без `TELEGRAM_BOT_TOKEN` сообщение пишется в лог. После заявки — окно правок до печати (см. «Заявка: проверка, окно правок, снимки»).
7. **Админка:** список заказов, смена статуса, «Отправить в печать», правка текстов, версии заказа, скачивание PDF. Сделана на Go (`backend/internal/admin`, `html/template`, без React), вход по HTTP Basic Auth (`ADMIN_PASSWORD`), POST защищены `http.CrossOriginProtection`. Отмена заявки открывает книгу клиенту. Скачивание PDF работает, когда у заявки есть `pdf_key` (шаг 8).
8. **Печатный PDF:** рендер через Chromium с вылетами, очередь, проверка на реальной типографии. Сделано: сервис `render/` (Playwright + Ghostscript + poppler + qpdf), очередь `backend/internal/render`, печатная страница `/print/<id заявки>?v=<версия заказа>&sheet=front|back|page&page=N` по подписанной ссылке (печатает снимок заказа этой версии). Состав и порядок файлов — из формата (`pdf_mode`, `pdf_order`; функция `render.Plan`): по умолчанию один `book.pdf` = передняя обложка, страницы, задняя обложка; `split` — `cover.pdf` + `block.pdf`. Каждый лист печатается отдельно и склеивается `qpdf` (память Chromium). PDF проверяется: страницы, размер, встроенные шрифты. RGB; `PDF_CMYK=true` — перевод в CMYK через Ghostscript. **Осталось:** проверка на реальной типографии; разовое зависание рендера тяжёлой книги (24 фото × 12 Мп) на 5,5 минут не воспроизвелось — в логе сервиса теперь время каждой страницы.
